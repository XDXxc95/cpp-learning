## 1. 指针回顾 | Pointer Refresher

变量有三要素：**名字、类型、地址**。`int x = 5;` 在内存某处占了 4 字节，`&x` 就是那处的地址。

```cpp
int x = 5;
int* p = &x;   // p 是「指向 int 的指针」，p 里装的是 x 的地址
*p = 10;       // 解引用 dereference：顺着 p 找到那个位置，写入 10
```

**心智模型**：`int* p = &x;` 之后，`*p` 和 `x` 是**同一个内存位置的两个名字**。改 `*p` 就是改 `x`。

指针的三条重要事实：

1. **指针的类型决定步长**。`int* p` 时 `p + 1` 跳过 4 字节（一个 int）；`char*` 时 +1 只跳 1 字节。所以数组遍历 `arr + i` 才能走到第 i 个元素。
2. **指针本身也是变量**，它自己也有地址（`&p` 类型是 `int**`，这里知道存在即可）。
3. **空指针用 `nullptr`**。`NULL` 是 C 遗留（整数 0 的别名），现代 C++ 一律写 `nullptr`。

回看 M1 练习 6 的 `swapPtr`：`swapPtr(&x, &y)` 把 x、y 的**地址**传给函数，函数里 `*a` 就是实参本体，所以能改到外面去。这就是「传值 vs 传地址」的区别——指针是 C/C++ 里把数据「借给」函数修改的经典手段。

## 2. 引用 | References

`int& r = x;` —— **r 是 x 的别名 alias**。之后 `r` 就是 `x` 的另一个名字，改 r 即改 x。

三条铁律：

| 铁律 | 说明 |
| --- | --- |
| **必须初始化** | 声明时就要绑定：`int& r;` 编译错误 |
| **不可改绑** | 绑定后锁死，`r = b;` 只是把 b 的值复制进来，r 仍指 a |
| **无空引用** | 不存在「引用没绑东西」——只要初始化了就一定有效 |

引用的底层就是指针（编译器帮你存了地址），但语法上像值：**不需要解引用符号，直接用**。这带来一个关键心理转变：函数参数是 `int& a` 时，函数里 `a` 直接就是实参。

### 引用 vs 指针（回答 M1 练习 6 的思考题）

| 维度 | 指针 Pointer | 引用 Reference |
| --- | --- | --- |
| 初始化 | 可延迟（但危险） | 必须绑定 |
| 改绑 | `p = &y;` 可以 | 绑定后锁死 |
| 空值 | 可为 `nullptr` | 不存在 |
| 语法 | 要写 `*p` 解引用 | 直接用，像普通变量 |
| 心智 | 「一个存地址的变量」 | 「另一个名字」 |

**何时用哪个**（练习 4 会实操）：

- **函数参数要借对象、避免拷贝**（如 `swap`、传 `vector`/结构体）→ **引用**。只读借用写 `const T&`。
- **可能「没有」**（查找函数找不到怎么办）→ **指针**。`nullptr` 就是「没有」，调用方判空。
- **需要重新指向**（遍历时移动）→ **指针**。
- **存进容器、做链表等结构** → **指针**（引用不能存进 vector，也不能「换人」）。

口诀：**能用引用用引用，需要「空」或「换人」才用指针。**

## 3. 栈与堆 | Stack vs Heap

程序内存粗略分三大区：

```text
高地址 ┌───────────────────────┐
       │       静态区 Static    │ ← 全局变量 / static 变量，程序一生都在
       ├───────────────────────┤
       │         堆 Heap        │ ← new 出来的，向上生长，手动释放
       │           ↑            │
       │     （空闲区 Free）      │
       │           ↓            │
       │         栈 Stack       │ ← 局部变量，向下生长，函数返回即销毁
       ├───────────────────────┤
       │       代码段 Code       │
低地址 └───────────────────────┘
```

> ⚠️ 这是教科书（Linux）布局。**Windows 上静态区往往在高地址**（本机实测：静态 `0x7ff6...` 最高、栈 `0x4233...`、堆 `0x1d23...` 最低）。规律是「三类各占各的区间、栈向下堆向上」，具体高低别背，跑一次 `examples/02/02` 看实地址。

| 特性 | 栈 Stack | 堆 Heap |
| --- | --- | --- |
| 谁管 | 编译器自动（函数返回即销毁） | 你手动（`new`/`delete`） |
| 速度 | 快（就挪个栈指针） | 慢（分配器查找/系统调用） |
| 大小 | 小（默认 ~1MB，深递归溢出崩） | 大（直到内存不够） |
| 典型成员 | 局部变量、参数、临时对象 | `new` 出来的对象、`vector`/`string` 内部缓冲区 |

**关键直觉**：栈变量死了就没了——**别把栈变量的地址/引用带出函数**（Bug 4 的现场）；要活得比函数长，就放堆上。

## 4. new / delete | 手动堆管理

```cpp
int* p = new int(42);   // 分配 + 初始化
delete p;               // 释放（单个对象）

int n = 3;
int* arr = new int[n];  // 运行时才知道大小 → 必须堆（栈数组要求编译期定长）
delete[] arr;           // 数组版，配 delete[]
```

**三条规矩**：

1. **`new` 配 `delete`，`new[]` 配 `delete[]`**——配错是未定义行为。
2. **谁 `new` 谁 `delete`**——函数里 new 给调用方用，责任写进注释（例 04 的 `makeArray`）。
3. **一个 `new` 恰好对应一个 `delete`**——多了双删，少了泄漏。

为什么不用 C 的 `malloc`/`free`：**`new` 自动调用构造函数，`delete` 自动调用析构函数**（例 03 的 `Point` 输出可见构造/析构顺序），类是 C++ 的命根子，所以手动管理必须走 new/delete。

**删完置空**：`delete p; p = nullptr;` —— 这是防「悬垂」的标准习惯。

> 预告：这一套手动规矩确实容易出错——**M5 的智能指针/RAII 就是来收编它的**。但先亲手踩一遍规矩，才理解自动管理好在哪。

## 5. 常见内存错误 | Common Memory Bugs

| # | 错误 | 症状 | 安全习惯 |
| --- | --- | --- | --- |
| 1 | **悬垂指针** Dangling（use-after-free）：`delete` 后还用 | 读垃圾值 / 随机崩溃 | 删完置空 + 用前判空 |
| 2 | **内存泄漏** Leak：`new` 了不 `delete` | 内存上涨，长跑程序挂 | 一个 new 一个 delete；尽早用 RAII |
| 3 | **双重释放** Double free：同一块删两次 | 堆损坏，崩 | 只删一次 + 置空 |
| 4 | **越界** Out-of-bounds：指针/数组越过边界 | 静默错值（M6 gdb 那次 `3 5 7 4`） | 边界检查；M3 起优先容器 |
| 5 | **返回局部变量地址/引用** | 悬垂（栈帧已销毁） | 按值返回；或由调用方传入 |

每种错误的「危险代码 → 症状 → 修复对照」都注释在 `examples/02/04_memory_bugs.cpp` 里（危险代码全部注释掉，取消注释即复现崩溃）。

**为什么内存 bug 可怕**：它们多半**不立刻报错**——泄漏等到内存耗尽、悬垂可能恰好读到旧值、越界静默算错。所以靠「编译器 + gdb + 好习惯」三件套，而不是等程序自己崩。

## 易错点 | Common Pitfalls

1. **`int* a, b;` 的陷阱**——a 是指针，b 是 int！要么 `int *a, *b;`，要么分行写。
2. **`int& r = 5;` 编译错误**（不能绑定字面量）；`const int& r = 5;` 可以（临时对象生命周期延长）。绑定临时对象的引用必须 const。
3. **两个 `&` 不是一回事**：`int& r = x;` 里的 `&` 是**声明引用**；`int* p = &x;` 里的 `&` 是**取地址**运算符。
4. **配对错**：`new[]` 配 `delete`，堆损坏。
5. **野指针**：`int* p; *p = 5;` —— 未初始化指针解引用，UB。声明即初始化：`int* p = nullptr;`。
6. **引用参数忘 const**：只读借用写 `const T&`，写 `T&` 会误导读者以为你要改它。
7. **两个指针指向同一块，只删一个置空**：另一个仍是悬垂（例 04 Bug 1 的 `q` 场景延伸）。
